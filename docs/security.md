# Security Controls & Threat Model

## Threat Model & Principles

Executing arbitrary code generated by an AI model introduces severe security risks including remote code execution, server privilege escalation, credential theft, and network attacks (e.g. DDoS or lateral network discovery).

The **Autonomous AI Coding Agent** adopts a strict defense-in-depth posture:

---

## 1. Sandbox Isolation Controls

| Threat / Risk Vector | Defense Strategy | Enforcement Mechanism |
| :--- | :--- | :--- |
| **Outbound / Inbound Network Exploits** | Network completely disabled | Docker parameter `network_disabled=True` |
| **Privilege Escalation** | Execution runs as unprivileged user | Docker user parameter `user="65534:65534"` (nobody/nogroup) |
| **Denial of Service (RAM Exhaustion)** | Memory capped per run | Docker `mem_limit="256m"` |
| **Denial of Service (CPU Hogging)** | CPU shares throttled | Docker `cpu_quota=100000` (1.0 CPU) |
| **Infinite Loops / Blocking Calls** | Enforced execution timeout | 15s execution timeout with SIGKILL fallback |
| **Host System File Tampering** | Read-only mounts & ephemeral storage | Read-only root filesystem (`read_only=True`), candidate code mounted `ro`, and ephemeral tmpfs scratch directory |
| **Test Suite Tampering** | Candidate cannot alter test harness | Tests reside in a separate directory mounted read-only and imported cleanly |
| **Docker Socket Abuse** | No host socket access | `/var/run/docker.sock` is **never** mounted inside execution containers |

---

## 2. Unsafe Execution Prevention Policy

- Under no circumstance does the application fall back to executing generated code on the host machine using `exec()`, `eval()`, or `subprocess.run()` if Docker is unavailable.
- If Docker daemon is absent or unreachable, the task is marked as `FAILED` with category `SANDBOX_ERROR` and a clear explanatory message is returned to the user.

---

## 3. Secret Protection & Data Privacy

- API keys (such as `LLM_API_KEY`) and server credentials are never passed as environment variables or mounted files into the execution sandbox container.
- SQLite database tables (`tasks` and `execution_reports`) store task prompts, code, and test traces, but explicitly exclude all authorization headers, tokens, and system secrets.
